2. Flow và transaction boundary

HTTP POST /api/v1/identity-profile-samples
  → validate request + Idempotency-Key
  → [transaction] sample + idempotency stored response + outbox PENDING
  → COMMIT
  → scheduled/local relay claims with lease
  → local delivery
  → [transaction] inbox receipt + local effect exactly once
  → outbox PUBLISHED

Failure after commit
  → outbox FAILED + sanitized error code + next_attempt_at
  → later claim/retry; original command transaction is unchanged
